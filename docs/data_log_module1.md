## Step 1: 匹配引用了撤稿论文的文献

**数据源:**
- `PaperReferences.csv`: 52G, 约 20 亿行，Dimensions 数据库全部引用关系
- `matched_output2.csv`: 50MB, 43,435 行撤稿论文名单

**方法:** DuckDB Semi-Join，扫描 52G CSV，保留 reference_ids 在撤稿名单中的行

**结果:**
| 指标 | 数值 |
|------|------|
| 撤稿论文总数 | 42,188 |
| 耗时 | 7.3 分钟 |
| 匹配行数 | 765,839 |
| 唯一 focal paper (i) | 647,439 |
| 平均每个 i 引用撤稿文献数 | 1.18 |
| 输出大小 | 21.9 MB |

**删除记录:** 约 20 亿行被排除（reference_ids 不在撤稿名单中的普通引用关系）

## Step 2c: 时间逻辑检验 (RYear - Year)

**结果:**
| 类别 | 行数 | 占比 |
|------|------|------|
| RYear-Year ≥ 0 (正常，引用在撤稿前) | 510,321 | 66.6% |
| RYear-Year < 0 (异常，引用时已撤稿) | 179,877 | 23.5% |
| RYear-Year NULL (缺失) | 76,055 | 9.9% |
| **合计** | **766,253** | **100%** |

**解释:**
- 66.6% 的引用行为发生在撤稿之前 → 这些是"无辜"的被牵连者
- 23.5% 在撤稿之后引用 → 明知被撤稿还引用，不纳入分析
- 9.9% 缺失 Year 或 RYear → 数据不完整，需要排除
